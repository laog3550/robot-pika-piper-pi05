# PI05 阶段工作流

只在 `laog3550/robot-pika-piper-pi05` 的独立克隆中使用本工作流。`pika_ros`
是上游参考，不是发布目标。

## 阶段判定

一个阶段必须有单一可验收结果，例如“将通用安全过滤节点实例化到左右臂并通过回放测试”。
零散编辑归入现有阶段；只有目标和验收条件均独立时才分配新编号。

从 `docs/status.md` 读取最大 `SNN`：继续同一目标时复用编号，新目标按顺序加一。
slug 使用小写 ASCII 与连字符。状态只能是 `计划中`、`进行中`、
`等待真机验收`、`验收通过` 或 `阻塞`；验证等级只能是 `静态`、`构建`、
`仿真/回放` 或 `真机`。

涉及控制输出、限位、速度、使能、停机、CAN、运动学、坐标变换或真机启动的
改动，若没有真实硬件记录，最高状态为 `等待真机验收`。静态、构建或回放成功
不能表述为真机验证。

## 开始前检查

1. 运行预检并记录初始 commit、分支和 changed paths。
2. `git fetch origin main`，确认 `origin/main` 存在且本地没有需要人工处理的分叉。
3. 通过 GitHub 查询目标仓库开放 PR；任何 head 以 `stage/` 开头的 PR 都会阻塞
   新阶段。
4. 从 `origin/main` 创建 `stage/SNN-<slug>`。不复用已合并或已关闭阶段分支。
5. 若任务开始前已有改动，可以继续调查，但不得把这些路径纳入阶段；若阶段必须
   修改同一路径，则停止并让用户处理归属。

## 验证与文档

运行与风险相称的测试。至少记录精确命令、退出结果和关键观察；不能执行的测试
写明原因与影响，不得写成通过。

`docs/status.md` 固定为：

```markdown
| 阶段 | 目标 | 状态 | 验证等级 | 更新时间 |
|---|---|---|---|---|
| S01 | ... | 验收通过 | 静态 | YYYY-MM-DD |
```

阶段报告 `docs/stages/SNN-<slug>.md` 使用以下栏目：

```markdown
# SNN 阶段标题

## 目标
## 完成内容
## 接口与兼容性
## 验证记录
## 真机证据
## 风险与限制
## 回滚方式
## 来源与许可证
```

真机证据应包含测试日期、非敏感硬件/环境描述、步骤、关键输出和停止方式。
没有真机测试时明确写“未执行”，禁止填写推测结果。来源栏目记录上游仓库、原路径、
commit/tag 和许可证；来源不清时阻塞复制源码。

README 仅在用户安装方式、公共 ROS 接口、目录结构或总体进度变化时更新。运行日志、
PR URL 和临时调查过程不写入 README。

## 发布门禁

在临时 scope 文件中列出本阶段全部 changed paths，再以 `--mode publish` 运行预检。
逐项检查：

- scope 覆盖所有且仅覆盖本阶段变更；
- diff 中没有凭据、令牌、私钥、真实 `.env`、设备序列号或私人地址；
- 没有 `build/`、`devel/`、`install/`、`logs/`、rosbag、日志、缓存或编辑器文件；
- 新二进制有明确必要性，新复制源码有许可证与来源记录；
- 所有必需测试通过，文档表述与实际验证等级一致。

任何门禁失败都不提交、不推送。不要 stash、重置、覆盖或删除用户文件。

## Git 与 PR

- 分支：`stage/SNN-<lowercase-slug>`
- 提交：`stage(SNN): <中文阶段摘要>`
- 目标：`main`
- 每阶段一个原子提交和一个 PR
- 禁止自动合并、强推、tag 和 Release

PR 正文格式：

```markdown
## 阶段目标

## 主要变更

## 验证
- 验证等级：静态 / 构建 / 仿真或回放 / 真机
- `<command>`：通过或失败及关键结果

## 真机状态

## 风险与回滚

## 文档
- `docs/stages/SNN-<slug>.md`
```

创建后回读远端 commit 和 PR，核对 head/base、文件范围与 URL。等待该 PR 合并后才
开始下一阶段；不主动合并。
