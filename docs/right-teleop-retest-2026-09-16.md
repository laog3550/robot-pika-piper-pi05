# 右侧直接遥操作联调记录（2026-09-16）

## 条件

用户确认右臂周围已清空、无异常，可立即急停。右 Pika 定位节点重启后，单侧活动检查
收到 1201 个位姿（119.8 Hz）、1302/1302 accurate 状态并检测到活动。
右侧驱动以 `auto_enable=false` 启动，触发前右臂六电机 disabled，未收到关节目标。

## 使能与触发

通过 `/right_arm/enable_srv_raw` 使能，六电机反馈 enabled，状态 NORMAL、CAN_CTRL、
err_code=0；使能后 5 秒六轴反馈范围均为零。随后调用 `/teleop_trigger_r`，厂商节点日志
确认进入 `start`。该厂商 Trigger 回调返回默认 `success=false`，但节点状态转换成功；
因此不能单独用该响应字段判断触发结果。

20 秒被动关联窗口收到 1146 个关节目标帧、382 组完整六轴目标和 12000 个关节反馈帧。
六轴均有近期目标与反馈样本，模式状态保持 CAN/MOVE_J，err_code=0。目标峰值变化从
0.0049 rad 到 0.0947 rad，反馈峰值变化从 0.0042 rad 到 0.0938 rad；这是多关节 IK
遥操作，单关节诊断器的“非选定目标变化”标记不代表异常。SocketCAN 接收仍不是控制器 ACK。

## 停止、返回与失能

再次调用 `/teleop_trigger_r`，节点日志确认 `close`。之后以 5% 速度发布一次共同支撑初始
姿态 `[0, 0, 0, 0, 0.567, 0] rad`。30 秒确认窗口结束时最大误差仍为 0.286814 rad，
因此没有自动失能；继续等待期间用户报告已手动失能，随即停止确认器和整个右侧遥操作／
驱动进程。

独立 SDK 与原始 CAN 各自复核发现六电机仍报告 enabled，同时状态为
EMERGENCY_STOP/STANDBY，说明现场操作当时进入停止状态但未实际失能。根据用户已明确要求的
失能状态，通过固定 SDK 发送一次 `DisableArm(7)`，未发送运动或夹爪指令；随后六电机均
报告 disabled。

失能后 3 秒六轴关节反馈范围均为零；六电机各 600 个高速样本，速度峰值均为
0.000 rad/s，电流峰值为 0.000–0.007 A。右侧遥操作和运动驱动已退出；双 Pika input-only
及双侧只读反馈继续运行。

## 结论

右 Pika 有效定位、活动检测、右侧使能、触发、持续多关节目标／反馈、关闭触发以及最终
失能链路均已实际执行。支撑姿态返回未在失能前确认到位，不能记为返回验收通过；后续需
根据 5% 速度和实际行程设置更长到位等待，并以反馈确认后再失能。
