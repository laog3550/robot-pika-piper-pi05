## 接口与行为

以下命令仅启动被动监听，不会使机械臂运动：

```bash
/usr/bin/python3 scripts/diagnose_piper_command_feedback.py \
  --side left --joint 2 --duration 30
```

`--joint` 指明预期唯一运动轴，不是给机械臂发送关节编号。
`--side` 仅接受 left/right，对应固定接口 left_piper/right_piper。
不需要 ROS、venv 或 SDK。时长 1–60 秒，只向终端输出聚合 JSON，
不保存原始 CAN 载荷、绝对目标、绝对位姿、电机位置、设备标识或逐帧日志。

- 三帧目标 0x155/0x156/0x157 必须按序在 20 ms 内观察齐全。
  缺帧、重复、乱序和采集结束的部分组均需要复核，不能直接称为发送失败。
- 运动目标出现前，先采集 20 个完整关节反馈组，六轴范围均不超过
  0.0005 rad，最后基准反馈距离第一目标帧不超过 100 ms。
  若监听启动太晚或基准不稳定，关联结论保持未确认，不补填事后基准。
- 目标相对监听基准、反馈相对同一基准分别统计最大绝对变化。
  非目标指令差异使用 0.00005 rad 比较容差（大于半个量化单位），
  这只是诊断对齐容差，不修改控制工具任何保护门限。
- 反馈与最近完整目标接收时间相差不超过 200 ms 时进行关联：
  非目标反馈超过 0.002 rad，分别标记近期目标已变化或近期目标未变化。
  超过 200 ms、未观察到完整目标、反馈接收间隔超过 100 ms 均标记证据不足。
- 汇总六轴电机速度峰值及状态字段组合。状态组合最多保留 64 种，
  超额只计数并标记；电机位置及固件查询载荷不解码。
- 至少每轴 3 个关联关节样本、10 个电机样本，并观察 CAN/MOVE J 状态，
  才能达到 `OBSERVATION_COMPLETE`；有异常或缺失则 `REVIEW_REQUIRED`。
  二者都不是安全验收通过，也不是根因确认。退出码分别为 0 和 1；
  环境、读取失败或中断返回 3。

## 解释边界与使用顺序

这里的时间是本机 recv 后的 monotonic 时间，不是硬件发送时间；
没有 kernel/hardware 时间戳，因此接收调度和缓冲延迟可能影响窗口判断。
本机监听可看到其它本机 socket 发出的回环帧，但这不是控制器逐帧 ACK。
三帧目标没有事务编号，按顺序配组是诊断约定；不能证明其它源未交错、
控制器已接受目标，或参考系在 enable/模式切换后未变化。
非目标目标差异可能来自基准采集与 enable 后的参考变化，不等于 ROS 目标串位。
速度非零是设备反馈，不是独立外部测量。

单独静置运行时无目标，输出 REVIEW_REQUIRED 是预期的证据不足，
不是要求启动运动来消除提示。工具不是 software stop，也不能替代硬件急停。
未来经独立批准的支撑下诊断复测，应先监听并留出至少 20 组稳定反馈的采集时间，
再运行既有带保护的单侧验收工具；不使用本工具生成运动，不修改保护阈值。
当前非目标运动已复现，尚无新的真机复测批准，不启动 Piper。
