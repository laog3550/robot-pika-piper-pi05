# S12 左右分侧低速验收

## 目标

先左后右完成方向、关节、限位、夹爪、超时和急停真机测试；S13 前禁止双臂同时使能。

## 完成内容

- 完成左臂只读驱动连通、首次使能/禁用和 J1 小步长往返。
- 根据真机重力下落风险，将协调器故障动作改为撤权和 software stop，默认禁止自动 disable。
- 下砸事件后建立两阶段低速验收工具：运动路径只 software stop 并保持使能，机械支撑后的
  disable 必须使用独立子命令；恢复停止状态后强制重新采集稳定基准。
- 将事件复核、分侧机械检查、防坠支撑、硬件急停、双人值守和重测批准做成 Git 忽略的现场
  门禁；缺少有效记录时 `move --apply` 在连接 ROS master 前失败。
- 新增仅使能稳定性检查，完全不创建关节目标发布器；J2 重测必须先通过该检查并记录分侧
  结果，且使能检查和运动测试分别使用一次性批准。
- 将目标到达、普通非目标漂移和回程判定改为连续 3 个样本确认；`0.002 rad` 漂移限值不变，
  单样本超过 `0.010 rad` 的严重非目标漂移仍立即停止。
- 新增原始 CAN 关节稳定性被动检查，只报告变化范围；支持排除目标关节后同步审计其余关节，
  不发送 CAN、不显示绝对角度或 payload。
- 新增 `0x251`–`0x256` 高速电机反馈被动诊断，汇总各关节样本数、速度峰值和电流峰值；
  验收进程也会在与命令相同的窗口内采集该证据，不发送 CAN、不输出电机位置或 payload。
- 新增固件查询 `check|apply` 入口和厂商兼容性升级单；默认检查不发帧，实际查询明确列出
  `0x472`/`0x4AF`，且源码禁止使能、模式、关节、夹爪、reset 和 stop 控制 API。
- 按 AGILEX 2026-07 产品资料清单修正固件路线门禁：`S-V1.8-2` 继续使用固定的
  `piper_sdk + piper_ros/noetic`，从 `S-V1.8-8` 起不得沿用该旧栈；版本匹配不解除事件门禁。
- 新增分侧关节参数 `check|apply` 查询入口；默认不发帧，显式执行只使用固定 SDK 初始化的
  `0x472`/`0x4AF` 查询并验证六轴角度、速度和加速度上限，不包含参数设置或运动 API。
- 修复验收 dry-run 在打印计划前加载外部 `piper_msgs` 的问题；无 `--apply` 时不再依赖外置
  Piper ROS 工作区，并继续在 ROS master、使能和运动之前返回。
- 补充真机运行 overlay 顺序：先加载固定 `pi05-upstream-ws`，再以 `--extend` 加载项目
  devel，使 `piper_msgs` 与 `pi05_control` 同时可见。
- 为进入遥操作前的安全诊断扩展 Pika 定位检查：`--require-motion` 仅判定左右跟踪器是否
  达到最小平移或旋转活动量，不输出位姿、不启动 Piper 驱动，也不发布控制命令。
- 外部审计窗口未覆盖重测后，将接收型原始 CAN 数据源直接嵌入验收进程；发送目标前先比较
  ROS 与 CAN 稳定基准，运动和回程验收均改用与命令同生命周期的原始 CAN 反馈。
- 修正原始 CAN 审计接入后的基准混用：整组外移和回程命令现在均从同一次原始 CAN 基准生成，
  避免把通过一致性检查但略有时差的 ROS 基准主动施加到非目标关节。

## 接口与兼容性

协调器不再提供自动故障 disable。公开人工 disable 接口保持不变，但仅允许机械支撑后使用。
新增 `single_arm_low_speed_acceptance.py enable-settle|move|supported-disable` 运维入口；默认仅显示计划，
所有真机动作均要求 `--apply` 和对应的现场确认参数。任何运动异常都会重新阻塞真机执行。

现场随后确认无人受伤，未发现机械臂、夹爪、线缆或周边设备损坏。
同日现场进一步确认：下砸事件已复核，左臂机械检查、防坠支撑、硬件急停、双人值守和
左臂重测批准均已满足。结果写入 Git 忽略且不含人员或设备标识的本机门禁文件；右臂机械
检查仍未记录。该确认只解除左臂重测前置阻塞，不构成 J2 或 S12 验收通过。

2026-09-14，使用修复后的两阶段工具再次测试左臂 J2：恢复停止、恢复后稳定基准采集和
使能均成功；以 `+0.005 rad`、5% 速度发送 J2 指令后，工具检测到非目标关节 J3 相对新基准

`LEFT_ENABLE_SETTLE=pass`。该结果只解除左臂 J2 重测的使能稳定性门禁，不代表 J2 通过。

随后获准进行一次左臂 J2 重测。恢复、使能和稳定基准成功后，验收工具以 5% 速度发送 4 次

在再次确认现场门禁后，使用内置原始 CAN 数据源执行下一次左臂 J2 重测。ROS 与 CAN 稳定
基准比较通过，随后以 5% 速度发送 12 次目标；约 `0.58 s` 后，原始 CAN 的非目标 J3 连续
3 个样本超过 `0.002 rad`，末次为 `-0.002304 rad`，工具返回 1。software stop、独立支撑
状态 disable 和驱动关闭均成功，右臂未启动，一次性批准已清空。该结果确认先前异常并非
仅由 ROS 组合快照造成，但尚不能区分机械联动、负载下微小顺应或控制器行为；现场运动观察
确认机械臂发生了小幅移动，没有观察到下砸、抖动、异响或其他异常。该观察不改变原始 CAN
连续漂移超过门限的结果，因此本次 J2 仍未通过。

离线核对固定版 URDF、Piper ROS 驱动和 `piper_sdk` 协议实现：J2 与 J3 使用独立关节及
transmission；命令按 J1/J2、J3/J4 分别编码，反馈也按 `0x2A5` 与 `0x2A6` 分别解码，未发现
mimic、数组串位或软件耦合变换。因此现有源码不能证明这次 J3 变化属于正常联动。

进一步核对本次 roslaunch 实际加载的官方 `piper_ros@ac41fcbc...` 文件及 ROS 日志：初始化
和每次关节命令均使用 `MotionCtrl_2` 的 `0x00` 位置-速度模式，日志连续记录 `vel_all: 5`；
`0xAD` 只存在于未调用的可选回零服务分支。只读参考工作区内嵌驱动使用 `0xAD`，但它不是
本次运行文件。此前把参考副本的 MIT/高跟随设置归因于本次运动的判断不成立。固定版 SDK
文档同时确认 `0x00` 为位置-速度模式、`0xAD` 为 MIT 模式，且高跟随模式下速度比例无效。

随后代码复核发现，原始 CAN 接入版虽然以 CAN 基准判定运动，却用较早的 ROS 基准构造所有
关节目标。ROS/CAN 一致性门禁允许最多 `0.002 rad` 的采样差，这会使未选关节收到返回 ROS
旧值的命令，是最新 J3 连续变化的一种充分软件解释。该缺陷已经修复并通过离线回放，但尚未
真机复测，因此不能把原因写成已由真机确认。

2026-09-14，经现场再次批准后重测该修复。仅启动左臂驱动，恢复停止、使能和稳定基准均
通过；J2 以 `+0.005 rad`、5% 发送 14 次后，原始 CAN 再次检测到非目标 J3 连续 3 个样本
超过 `0.002 rad`，末次为 `-0.002775 rad`，测试返回 1。程序立即 software stop，随后在
已确认机械支撑条件下 disable 成功，并关闭驱动和 ROS master；右臂未启动，一次性批准已
清空。关闭后左侧 CAN 为 `ERROR-ACTIVE`，总线错误、warning、passive 和 bus-off 均为 0。
这次结果排除了“仅由 ROS 旧基准作为非目标命令”这一单一原因；尚无厂商跟随误差依据，不能
把该连续位移判为可接受。为后续诊断，工具将额外记录 ROS/CAN 最大相对基准差和失败时目标
关节相对位移，但不记录绝对关节角或设备标识。操作人员随后确认现场没有问题，未报告下砸、
抖动、异响或其他异常；该反馈没有明确具体关节的可见位移，不能替代原始 CAN 位移门禁。

保持驱动关闭和机械臂禁用，对左侧高速反馈被动采样 5 秒：J1–J6 各收到 1000 个样本，
六关节速度峰值均为 `0.000 rad/s`，绝对电流峰值分别为 `0.061`、`0.071`、`0.086`、
`0.037`、`0.037`、`0.044 A`，命令返回 0。该结果确认高速反馈源完整且静止基线正常；它不
包含运动窗口，因此不能单独解释或放行 J2 重测。

同日现场批准带高速电机反馈再次测试左臂 J2。ROS/CAN 稳定基准最大差为 J5
`0.000263 rad`，通过一致性门禁；以 `+0.005 rad`、5% 发送目标后，J2 相对基准超过工具的
`0.020 rad` 绝对保护窗口，测试返回 1 并立即 software stop。同步高速反馈各收到 42 个样本：
J2 速度/电流峰值为 `0.205 rad/s`、`0.633 A`，J3 为 `0.099 rad/s`、`0.962 A`；J1 速度
为零，J4 仅 `0.001 rad/s`。该证据确认 J2 超步长期间 J3 电机也发生实际运动，不能解释为
单纯位置帧噪声。随后在机械支撑条件下 disable 成功，关闭驱动和 ROS master；右臂未启动，
CAN 无总线错误。一次性批准以及事故复核、左臂机械检查和左臂无命令使能结果均已清空，禁止
未经新一轮现场复核再次运动。操作人员现场确认机械臂发生移动，但没有观察到下砸、抖动、
异响或其他异常；该观察与高速反馈的实际运动结论一致，但不能使超过保护窗口的运动通过。

固定 SDK 运行时复核确认 `MotionCtrl_2` 参数顺序与文档一致，本次第四参数为默认 `0x00`
位置-速度模式，速度百分比为 5；`JointCtrl` 仍以独立 J1/J2、J3/J4、J5/J6 帧发送
`0.001°` 单位目标。因此目前没有证据支持通过修改模式位、关节映射或放宽软件门限继续测试。

在机械臂禁用且驱动、ROS master 均关闭时，经现场确认分别执行左右固件查询，结果均为
`S-V1.8-2`。该版本位于官方 `S-V1.6-3` URDF 分界之后，排除了误用旧 URDF 这一项；查询
本身不构成 SDK 运动兼容性证明，J2 超步长和 J3 同步运动仍需厂商解释。查询结束后连接均
已关闭，期间未使能机械臂或发送运动指令。

2026-09-15 继续沿用该版本完成查询式参数核验。左右 J1–J6 的角度上下限、最大速度和最大
加速度均完整返回且逐项一致；最大速度均为 `0.300 rad/s`，最大加速度均为 `0.500 rad/s²`。
紧随其后的被动 CAN 窗口没有控制/配置帧或总线错误。查询只发送 `0x472`/`0x4AF`，未使能、
未修改参数、未发送关节或夹爪命令，现场没有进行运动验收。

同日左臂无目标使能稳定性检查返回 0，反馈最大偏移为零；之后按既定顺序完成 software stop、
机械支撑下独立 disable 和驱动关闭。本项只证明该次使能建立过程的反馈稳定性；操作员尚未
报告外观、声音和支撑受力观察，因此不把它写成完整现场观察通过，也不自动开放运动门禁。

尝试进入摇操输入验证时，定位器虽然持续发布左右位姿，但两侧状态均为不准确且没有检测到
活动。该结果只说明当前跟踪不可用，未启动 Piper 驱动或遥操作控制节点。上游 locator 会在
ROS 启动摘要中展开设备映射；本次对应的单一 ROS 运行日志目录已立即删除，仓库未记录设备
标识。后续不得使用会展开标识的上游 launch 直接采集验收日志。

随后核对 AGILEX 官方公开问题记录：维护者确认 `S-V1.8-2` 存在 Leader/Follower 状态、
零点/参考和限位参数风险；0.6.2 发布说明仅包含 CAN 收发 bus 分离等改动。厂商更新的
2026-07 产品资料清单同时明确：低于 `S-V1.8-8` 的机械臂仍使用 `piper_sdk` 与
`piper_ros/noetic`。因此项目保留风险说明和真实事件阻塞，但撤销把 `S-V1.8-2` 本身视为
软件不兼容的结论；按设备负责人决定，本阶段不升级 SDK、不刷写固件、不迁移控制栈。

## 风险与限制

- 未支撑机械臂 disable 后可能受重力下落；修复验证前暂停后续运动。
- J2 首测未达到反馈位移阈值，恢复停止状态后的复测又发现恢复前后反馈基准不连续；J3–J6、
  夹爪、超时、急停及整套右臂验收尚未执行。
- software stop 不等同硬件急停，保持使能仍有储能和意外运动风险。
- J2 复测发生过机械臂下砸安全事件。现场已完成左臂检查、无命令使能稳定性测试和重测
  前置确认；右臂机械检查尚未记录。
- 修复后 J2 重测虽然安全停止并成功执行支撑后 disable，但出现非目标关节漂移超过
  `0.002 rad`；确认具体关节、漂移量和原因前，S12 再次阻塞。
- 本次保护性中止的软件记录为非目标 J3 漂移 `-0.005094 rad`，但操作人员现场确认机械臂
  没有发生可见移动。反馈值与现场观察不一致的原因尚未确认，不能据此解除阻塞。
- 连续样本修复和原始 CAN 对照工具尚未经过运动中的真机验证；S12 保持阻塞，禁止直接开始
  J3 或右臂测试。
- 第二次修复后重测仍出现 ROS 单样本异常，且外部被动检查窗口未覆盖运动时刻。再次测试前
  已让验收程序自身持有并校验覆盖整个运动窗口的接收型 CAN 审计；该修复仅通过离线测试，
  最新重测已取得原始 CAN 连续漂移证据，因此反馈拼接假阳性不再是唯一解释。
- 原始 CAN 显示 J2 小步长期间 J3 发生超过限值的连续反馈变化。没有厂商依据前不得通过
  放宽漂移阈值、加入 J3 补偿命令或继续其他关节来绕过。
- 参考 `sensor_tools/open_multi_sensor.launch` 把右侧 `teleop_status`、`localization_status` 和
  `arm_control_status` 错误重映射到左侧话题，并硬编码默认设备参数；不得直接作为双手遥操作
  入口。S14 必须建立本项目的分侧输入封装和图审计后再连接机械臂。
- 已修复可能主动造成非目标关节位移的 ROS/CAN 基准混用，但修复后真机重测仍出现 J3 连续
  漂移；S12 继续阻塞。再次运动前应先取得厂商允许的关节跟随误差依据，或增加能够区分 J3
  实际电机运动与负载顺应的只读证据；不得直接进入 J3 或右臂。
- 高速反馈进一步确认 J2 超出 `0.020 rad` 保护窗口且 J3 电机同步运动。该现象已经超过
  “允许跟随误差”能单独解释的范围；在厂商完成控制/固件兼容性分析或提供安全恢复方案前，
  禁止再次发送关节运动命令。
- 左右当前 `S-V1.8-2` 与固定旧栈符合厂商版本矩阵，但软件路线兼容不等于本次异常已关闭。
  固件参数、模式/主从角色和实际 J2/J3 行为未完成只读诊断闭环前，禁止再次使能或运动。

## 回滚方式

保持驱动关闭，在不进入运动范围的前提下机械固定并按现场安全程序隔离能源。不得仅为回滚
软件而重新使能机械臂。撤销本阶段提交可恢复代码，但不得恢复已证明危险的自动 disable
运行策略或“返回失败后自动 disable”的验收流程。
