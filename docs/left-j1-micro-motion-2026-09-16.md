# 左 J1 单次微动异常记录（2026-09-16）

## 授权与基准

用户要求发布微小运动指令，沿用已确认的左臂现场条件；在读取到
EMERGENCY_STOP 后，用户确认是此前软件 stop，并明确允许解除、执行本次左 J1 微动。
Pika 充电期间未运行新的遥操作或 IK，没有操作右臂。

发送前左 CAN 5 秒 15,201 帧、20/20 反馈 ID、无控制帧；随后 3 秒六轴反馈范围为零。
测试内部 2 秒基准要求六电机 enabled、六轴反馈完整、新鲜、静止。
使用固定 SDK `ConnectPort(piper_init=False)`，不发送初始化查询。

## 指令

只调用一次各接口：

```python
arm.MotionCtrl_1(emergency_stop=2)
arm.MotionCtrl_2(ctrl_mode=1, move_mode=1, move_spd_rate_ctrl=5, is_mit_mode=0)
arm.JointCtrl(*target)
```

`target` 来自新鲜六轴反馈，仅 J1 增加 57 个 0.001° 单位，即 +0.000994838 rad。
J2–J6 保持各自基准反馈值；未发送夹爪、归零、失能或安装参数配置指令。
接收观察到 0x150、0x151、0x155、0x156、0x157 各一帧。
这些帧的接收不等同于控制器 ACK，本次记录未保存原始 payload。

## 异常与停止

非目标关节 J2 连续三个采样超过相对基准 0.002 rad 的本次观察界限，程序发送一次
`MotionCtrl_1(emergency_stop=1)`，终止观察，返回非零。未重试、未自动回程。

终止前累计最大绝对反馈变化（rad）：

| 关节 | 最大绝对变化 | 最后采样相对基准变化 |
|---|---:|---:|
| J1 | 0.057247 | +0.057247 |
| J2 | 0.034645 | -0.018658 |
| J3 | 0.000000 | 0.000000 |
| J4 | 0.130324 | +0.130324 |
| J5 | 0.479896 | -0.479896 |
| J6 | 0.064403 | -0.064403 |

J1–J6 收到关节样本各 121、121、120、120、120、120。
程序在异常触发时读取的六电机缓存仍为 enabled。
各 CAN 关节对异步更新，最后采样值并非六轴严格同一时刻的状态。

## 停止后独立核验

- 5 秒六轴关节反馈范围全部为零。
- 5 秒六轴电机各 1,000 高速样本，速度峰值全部 0.000 rad/s，电流峰值全部 0.000 A。
- 独立 SDK 读取：STANDBY、EMERGENCY_STOP、MOVE_J、REACH_TARGET_POS_FAILED、err_code=0。
- 六电机报告 disabled。程序未发送 disable；不能据此确定是控制器急停响应、现场
  硬件操作或其他原因导致失能。

## 现场补充

用户随后确认“现场几乎没动”，并指出机械结构会牵引其他关节产生微小变化。
因此上述 CAN 数值不能直接解释为同等幅度的实际关节运动；此前对“大幅运动”的
表述不准确。程序触发 0.002 rad 观察界限只证明预设反馈判据被触发，不证明机械异常。
现场观察与反馈量级不一致仍待解释，见 [只读解码核查](feedback-decoding-review-2026-09-16.md)。

## 结论

软件观察判据未通过。约 0.001 rad 的 J1 单次目标伴随较大的目标与非目标反馈数值变化，
不能作为运动或遥操作通过记录。停止后反馈静止不等同于独立物理安全确认。
没有据此唯一判定固件、机械或协议原因；应先复核实际运动、目标编码、设备端
参考状态与固件兼容性，再决定后续测试。保留急停，不再追加运动。
