# S02 安全约束

状态：**安全需求已冻结；当前参考实现尚未满足真机放行条件。**

> 历史文档（S02 时期）。本文写于厂商链路直连重构之前，其中的状态机、阶段编号、
> 接口名和门禁清单对应当时或已删除的实现，保留用于追溯安全需求本身，不代表当前
> 代码。当前运行链路见 [直接遥操作](direct-teleop.md) 与 [双臂架构](architecture.md)，
> 实际状态与剩余阻塞项见 [部署进度](status.md)。
>
> 与实现无关的约束仍然有效，包括：急停必须是独立硬件功能（第 2 条）；禁止远程
> 无人值守使能（第 8 条）；配置与记录不得包含设备序列号等敏感标识（第 10 条）；
> 失能前必须先回到可支撑姿态；软件服务返回成功不能作为机械臂已安全停止的证据
> （[停止语义](#停止语义)）。

## 不可妥协约束

1. S02 只做盘点和文档，不启动控制链、不发送 CAN 帧、不使能、不回零、不执行手势返回，也不迁移控制代码。
2. 急停必须为独立硬件安全功能，不能依赖 ROS、PI05、网络、Python 节点或 `/stop_srv`。
3. 上电和驱动启动默认禁用，`auto_enable=false`；使能只能由现场操作员在工作区清空、急停可触达且反馈有效后明确发起。
   （历史注：本条不描述现状。当前直接入口 `scripts/start_*.sh` 的 `auto_enable` 默认为
   `true`，启动驱动后会自动使能；只有平滑会话 `scripts/run_smoothed_teleop.sh --apply`
   以 `auto_enable:=false` 启动，再由脚本按 `reset → enable` 明确使能。需要手动使能时
   显式传 `auto_enable:=false`。）
4. 在收到新鲜、完整、数值有限的真实关节反馈前，任何运动目标都不得透传。重新使能和新遥操作会话必须以真实反馈重新初始化，旧目标必须失效。
5. 定位无效、命令超时、ROS 时间跳变、节点退出、CAN 错误、关节通信错误或状态不明时必须进入确定的安全状态。仅停止发布新位置目标不等同于禁用或急停。
6. 所有控制入口必须有唯一所有者。原始使能、笛卡尔命令、夹爪服务、回零、reset 等绕过入口必须隔离、重映射或禁用。
7. 首次运动前逐关节确认顺序、正方向、零位、软硬限位、单位、夹爪范围、安装方向、负载和运动包络。
8. 首次测试空载、低速、小步长、单关节、现场双人复核；一人操作，一人守急停。不得远程无人值守使能。
9. 任何自动返回/回零都是运动功能，不是停止功能。未经单独风险评估和可中断性验证，必须关闭。
   （历史注：自动返回已在平滑会话中实现并分侧真机验证。它的可中断边界是：输入超时即
   停止发布整组目标，异常退出时保留驱动并打印 PID 与日志位置，不自动失能；由操作员
   决定下一步。仍不得把它当作停止功能。）
10. 配置与记录不得包含设备序列号、密钥、账号、IP/MAC、人员或场地敏感信息。
11. 左右臂必须使用独立命名空间和唯一控制所有者；任何侧别不明确的运动接口都不得公开。
12. 双手会话中任一侧定位、反馈、通信或安全节点失效时，必须撤销双侧会话并锁存故障；
    具体 hold/stop/disable 动作必须在真机分侧验证后批准。
    （历史注：当前链路没有跨侧联锁，两侧会话相互独立；本条仍是未满足的需求。）
13. 双臂同时运动前，必须完成共享工作区、臂间碰撞、线缆牵拉和双侧急停覆盖评审。
    （历史注：对应硬件清单 H-08/H-10，仍为未闭环的阻塞项。）

## 状态机冻结要求

```text
DISCONNECTED
    │ 通信与反馈有效
    ▼
DISABLED ── 人工使能 + 安全前置通过 ──► ENABLED_HOLD
   ▲                                      │ 新会话 + 定位有效
   │                                      ▼
   └──── 故障/禁用/状态不明 ◄──────── TELEOP_ACTIVE
                         │
                         ▼
                  FAULT_LATCHED
```

- `DISCONNECTED`、`DISABLED`、`FAULT_LATCHED` 不允许发运动命令。
- `ENABLED_HOLD` 只能保持实测位置，不得恢复缓存目标。
- 进入 `TELEOP_ACTIVE` 需要使能后的新会话、有效定位、新鲜反馈和新鲜命令同时成立。
- 故障必须锁存并要求人工确认；Trigger 的切换语义不能用来推断安全状态。

## 当前参考实现的缺口

| ID | 观察 | 风险 | 后续放行要求 |
|---|---|---|---|
| S-01 | Piper driver 仍订阅 `/enable_flag`、`/pos_cmd`，并公开原始夹爪、reset、回零服务 | 可绕过安全过滤器直接使能或运动 | 在 bringup 中隔离/禁用并测试无旁路 |
| S-02 | `/go_zero_srv` 直接发零位且参考实现使用 50% 速度 | 大幅意外运动 | 默认不启动；单独设计受限回零流程 |
| S-03 | 超时/定位丢失只停止遥操作输出，没有证据表明会禁用或调用 Piper stop | 最后位置模式仍保持；故障语义不完整 | 定义并验证 hold/stop/disable 分级策略 |
| S-04 | `hold_position_on_enable` 是本地未提交补丁 | 行为未经版本固定和测试 | 独立代码审查、仿真/台架故障注入 |
| S-05 | 参考实现只有右臂过滤器/launch/桥，且未提交于参考 SHA | 直接复制会形成右侧特例，双臂无法一致复现 | 迁移为同一通用实现，以参数/remap 实例化左右两侧 |
| S-06 | S06 已将共享 YAML 从 30 修正为 15，但尚未真机批准 | 参数一致不代表速度已经安全 | 首次运动值仍需左右分侧审批和验证 |
| S-07 | 夹爪手势阈值与驱动中的夹爪范围描述不一致 | 误触发自动返回或范围错误 | `double_gripper_return=false`，现场标定后再评估 |
| S-08 | `/joint_states_r` 可能有 IK 与可选回零逻辑两个发布者 | 命令竞争 | 强制单发布者并在启动前审计 ROS graph |
| S-09 | `teleop_piper_publish.py` 的 PoseStamped orientation 字段承载 Euler 分量而非四元数 | 非标准语义易被误接 | 接口改名/自定义消息或明确适配，不对外复用 |
| S-10 | 未见硬件急停、供电、限位、负载、Piper 型号/固件的现场证据 | 无法判断真实风险 | 完成硬件清单 H-03/H-08/H-09/H-10 |
| S-11 | 参考 launch/脚本含机器唯一硬件标识字面量 | 隐私泄露且不可移植 | 不复制字面量；仅用本机私有配置/udev 映射 |
| S-12 | 现有参考接口存在未命名空间化的 `/arm_status`、`/enable_srv` 等全局名称 | 两个驱动会冲突或串侧 | S09 已将全部原始接口分侧映射；S11 统一 launch 保持其为内部边界，公开控制只归双臂协调器 |
| S-13 | 尚无单侧故障时另一侧的确定行为和臂间碰撞策略 | 一侧失效、另一侧继续运动可能放大风险 | S11 已完成跨侧软件回放；S15 完成真机故障注入，S13 前完成共享空间评审 |

S11 已在无硬件回放中实现并验证“任一侧故障撤销双侧授权，再双侧 stop、最后双侧
disable”的顺序，也增加了协调器授权租约和只读 ROS 图所有权审计。该证据不能证明官方
stop/disable 在真机上的制动、下坠或时序效果；S12 前仍不得把软件联锁视为硬件急停。
ROS 1 没有访问控制，`*_raw` 只能通过受控 ROS master、启动清单和运行时图审计维持内部
边界，不能抵御已获得 ROS master 访问权的恶意节点。

S12 左臂真机使能/禁用和 J1 小步长测试确认：未支撑机械臂在 disable 后存在重力下落
风险。协调器自动故障动作因此修正为“撤权 + software stop”，默认禁止自动 disable。
常规停机必须先在使能状态低速回到可支撑姿态，再由现场人员机械支撑后人工 disable。

S12 左臂 J2 复测发生安全事件：恢复快速停止后，测试使用了恢复前采集的关节基准；返回
该基准超时后，异常清理执行 software stop 和 disable，现场观察到机械臂移动后直接下砸，
没有缓慢返回初始位置。日志中的服务成功不能作为机械臂已处于安全姿态的证据。事件检查、
机械固定和恢复流程修复完成前，禁止左右臂继续使能、复位、回零或运动验收；禁止在重力可
驱动机械臂下落的姿态执行 disable。异常路径不得把“返回目标失败”继续转换为自动 disable。

> 历史注：上面这条禁令当时生效，现已被用户现场复测取代——用户自行测试确认无异常，并
> 要求继续推进；随后左右单臂完成了真机使能、平滑遥操作、自动返回支撑姿态和确认后失能，
> 见 [项目进度](project-progress.md)。禁令中与实现无关的两条仍然有效：不得把“返回目标
> 失败”转换为自动 disable（现在的会话脚本在未确认到位时保留驱动并报错退出），以及不得
> 在重力可驱动下落的姿态执行 disable。

左右实机固件均已确认为 `S-V1.8-2`。AGILEX 当前产品资料清单明确将低于 `S-V1.8-8`
（不含 `S-V1.8-8`）的固件分配到 `piper_sdk + piper_ros/noetic` 路线，当前组合因此通过
软件路线检查。公开问题记录中的模式/零点参考和参数风险仍须保留；更重要的是，本机已经
出现超出保护窗口的真实运动异常。固件版本匹配不能解除事件门禁，不得以放宽阈值、加入
补偿或继续试运动替代诊断闭环。

## 阶段门禁

### 允许在 S02 执行

- 读取仓库、提交 SHA、package/launch/source 和构建元数据。
- 在不启动控制节点的前提下运行系统、USB、CAN、串口的软件枚举命令。
- 机械臂保持禁用时读取已有 ROS 状态、话题类型、频率和发布者关系。
- 断电隔离后进行接线、终端和安装检查。

### S02 禁止执行

- `cansend`、CAN 日志回放或任何自制帧注入。
- 调用 `/dual_arm/enable_srv`、任一 `/left_arm/*_raw`、`/right_arm/*_raw` 或 `/teleop_trigger_l|r`。
- 向任一侧原始/过滤运动话题、`/enable_flag`、`/pos_cmd` 或 `/gripper_l|r/ctrl` 发布。
- 运行会自动使能的上游 launch，或把 `auto_enable` 改为 true。
- 复制/迁移参考区的控制脚本或 launch 到目标仓库。

## 后续真机放行检查表

以下是后续阶段门禁，不授权在 S02 执行：

- [ ] 机械、电气、负载与工作空间检查签字完成。
- [ ] 急停在控制器运行、ROS 退出和主机失联三种条件下均验证有效。
- [ ] CAN error counters 为零或在批准阈值内，拔线/总线错误可被检测并锁存。
- [ ] 状态反馈的顺序、单位、时间戳、频率、NaN/Inf 和断流处理验证完成。
- [ ] 所有旁路控制入口均不可由非授权节点访问。
- [ ] 禁用→使能不会执行旧目标；命令源重启也不会恢复旧目标。
- [ ] 超时、定位丢失、IK 超限、节点崩溃和 ROS 时间异常的期望安全动作均通过故障注入。
- [ ] 首次运动参数由现场负责人批准，自动返回保持关闭。

## 停止语义

文档和运维界面必须严格区分：

- **hold**：停止更新目标并保持当前位置，机械臂仍可能有力；
- **software stop**：请求控制器停止运动，不保证切断驱动力；
- **disable**：驱动去使能，具体制动/下坠行为必须按实物验证；
- **emergency stop**：独立硬件安全动作。

任何文档不得把 ROS 服务成功响应当作机械臂已安全停止的唯一证据。
